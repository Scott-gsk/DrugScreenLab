# DrugScreenLab 数据目录

本目录是项目数据资产的唯一根目录。数据集来源、可获取完整性、配对情况和信息范围统一记录在 [DATA_CATALOG.md](./DATA_CATALOG.md)；机器可读的版本、路径、校验值和来源记录统一放在 `registry/`。

## 标准目录

| 路径 | 内容 | 修改规则 |
|---|---|---|
| `raw/` | 从公开或受控来源取得的原始文件 | 只读保存，不覆盖、不补值、不重排 |
| `external/` | 第三方代码或第三方已经处理的数据 | 保留来源版本和许可信息 |
| `interim/` | 可以从来源文件重新生成的中间文件 | 必须能追溯到输入和生成脚本 |
| `processed/` | 经过身份映射、配对或特征处理的数据 | 使用新版本目录，不覆盖旧版本 |
| `splits/` | 训练、验证、测试或其他分组文件 | 记录分组单位、种子、版本和输入哈希 |
| `registry/` | 数据登记、获取清单和受限资源登记 | 小型 JSON；保持机器可读 |
| `artifacts/` | 数据审计回执、质量检查和大体量运行产物 | 不作为原始数据来源 |
| `schemas/` | 共享数据格式定义 | 当前保留为空，待出现稳定共享格式后使用 |

除以上目录和根目录文档外，不在 `data/` 根目录新增按日期、论文或临时任务命名的数据文件夹。获取批次应分别放入 `raw/<dataset>/<version>/` 和 `artifacts/resource_acquisition_<date>/`。

## 命名规则

- 数据集目录使用稳定的小写名称，例如 `ctrp_v2/`、`gse303509/`。
- 来源版本使用 `v1`、`v2` 或明确发布版本；日期只用于获取批次和审计回执。
- 原始文件保留来源文件名；处理文件使用能够说明内容的名称，不使用 `final`、`new`、`temp`。
- 登记 ID 使用小写英文、数字和下划线，并包含数据集、版本和资产类型。
- 完全相同的数据文件只保留一份；其他登记通过相对路径引用该文件。

## 登记要求

每项正式数据资产至少记录：

- 稳定数据集 ID 和版本；
- 来源机构、论文或数据库编号；
- `data/` 下的相对路径；
- 文件大小和 SHA256，或包含逐文件校验值的清单；
- 原始、外部、中间、处理后或划分文件类型；
- 已知缺项、身份对应范围和可重复生成方式。

`registry/datasets*.json` 会被数据注册表验证程序自动读取，必须是符合统一字段要求的登记列表。其他说明性 JSON 不使用 `datasets` 前缀。

## 完整性口径

- **来源文件齐备**：发布方实际提供的文件已经取得并校验。
- **表达—响应配对完整**：同一样本同时具有基线分子特征、药物响应和可靠身份。
- **部分完整**：文件已取得，但缺少另一种数据模态、部分样本或身份对照。
- **公开未找到**：已检查的公开入口没有所需文件，不等于数据永久不存在。
- **受控访问**：需要数据库审批或作者授权后才能取得。
- **辅助数据**：可提供表达、基因依赖、药物扰动或知识关系，但没有完整药物响应标签。

大型数据文件不提交到 Git。Git 只保留目录说明、登记、格式定义、紧凑审计结果和足以复现处理过程的代码。
