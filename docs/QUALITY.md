# 质量规范

合并前必须通过架构测试。Reviewer 应独立检查数据泄漏、数据划分正确性、复现性、
指标有效性和仓库污染，不得仅依赖实现作者的结论。

任何实验结论都应能追溯到明确的数据集版本、数据划分、配置、运行环境和产物。
发现这些要素缺失时，应返回 `INCONCLUSIVE` 或 `INVALID`，并说明原因。

## 收口工程卫生硬性验收（2026-09-22 增补）

实验或会话收口时，以下三项为硬性验收，未通过不得宣称收口完成：

1. **本任务临时文件已处置**：按 [AGENTS.md](../AGENTS.md) 检查本任务的临时子目录，转正、归档或安全删除；中断恢复所需文件注明用途与处理条件。不要求清空整个 `tmp/`，不处理其他任务的文件。
2. **DRAFT 处置决定**：当轮产生的所有 DRAFT 文件均已给出明确处置决定
   （转正 / 归档 / 删除），无悬置 DRAFT。
   检查：能逐个说出当轮 DRAFT 文件的去向；无新增未登记 DRAFT。
3. **本任务改动可交代**：检查 `git status --porcelain`，本次修改、新文件与残留都有明确用途及处置状态。普通交付允许未提交修改，不以整个工作树为空作为完成条件；不得清理或提交其他任务改动。稳定版本推送仍须满足 `AGENTS.md` 的测试、状态一致及工作树要求。
