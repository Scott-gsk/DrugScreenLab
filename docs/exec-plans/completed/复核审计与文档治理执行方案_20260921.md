# DrugScreenLab 实验复核、研究推进与文档治理完整执行方案

> 状态：**已收口（2026-09-22）**——阶段 0~7 全部完成，EXP-031~035 见注册表与记录；收口报告 `../reports/program_closeout_20260922.md`。本文件保留为第三波执行记录，不再作为待办计划。

## 一、目标、范围与不可擅自变更的原则

本方案完整保留前几版中的报告修订、数据准入、评估修复、公平对照、统计检验和实验治理要求，并纳入六项研究质疑及项目文档规范。后续执行 Agent 必须依据本方案完成验证，不能自行将其缩减为“更换指标”“换一个复杂模型”或“重写报告”。

### 1. 最终需要回答的问题

1. 现有周报中的数字、实验设置和结论分别有多少可信，哪些需要更正或重跑？
2. 药敏预测失败发生在来源细胞系泛化、跨研究泛化，还是细胞系到类器官的迁移阶段？
3. 当前结果受评价方法、样本与标签质量、模型能力、监督条件中的哪些因素影响？
4. 在公平条件下，直接预测、扰动介导预测和融合分别能够做到什么？
5. 控制疾病构成后，哪些跨体系差异仍存在，哪些与预测误差有关？
6. 基因依赖任务能否发现可重复的患者差异信号，模型和数据分别构成什么限制？

主要应用固定为：**为未见患者排列完整的可评估药物清单**。前 1–3 个药物选择质量作为辅助评价。零目标药敏标签与少量目标药敏标签的情形分别研究。

### 2. 执行原则

- 先核验，再解释；同时寻找支持与反对质疑的证据。
- 保留真实负结果，也保留有效的正结果；不得为了“纠错”预设旧实验全部无效。
- 旧实验用于定位问题和提供历史证据，不能绕过新协议的数据与评估要求。
- 保留直接、间接和融合方向。有限的复杂模型诊断不以简单模型先成功为前提；持续扩大模型与计算投入则必须有证据支持。
- 工程修复与研究结论分开。测试通过只证明所覆盖的软件行为正确，不能写成科学结论成立。
- 对已知错误必须纠正；对尚未验证的解释必须保留不确定性。
- 不以“相关性低”直接判无效，也不以“大样本显著”直接判实用。
- 不把弱模型、单次运行或训练集表现称为“数据上限”。
- 本方案确定研究顺序和约束。每个正式实验仍需形成完整预注册配置后启动，执行 Agent 不得自行补定关键科学选择。

## 二、工作包 A：历史证据审计与周报修订

### A1. 建立证据清单

审计范围以周报涉及的实验为主，并回溯必要的来源泛化实验。依次检查：

**原始来源与数据登记 → 数据合同 → 实际代码和配置 → 运行产物 → 指标计算 → 实验记录 → 周报结论。**

每项重要结论建立一条证据记录：

| 字段 | 必须记录的内容 |
|---|---|
| 原主张 | 原文位置及具体结论 |
| 实际设置 | 数据、监督条件、模型、划分、指标 |
| 证据来源 | 产物路径、字段、配置及代码版本 |
| 复核发现 | 数字正确与否、比较是否公平、合同是否执行 |
| 影响范围 | 仅影响表述，还是影响数值、训练、统计判定 |
| 处理方式 | 保留、更正、降为探索、待重算、待重训 |
| 当前结论 | 能说明什么、不能说明什么 |
| 后续验证 | 对应工作包与验收条件 |

证据缺失时明确标注缺少什么。不得根据文件名、日志中的“成功”或旧报告文字推定实验有效。

### A2. 必须处理的已知问题

| 问题 | 必须采取的处理 |
|---|---|
| 扰动相关性约 0.05 被写成约 0.5 | 从对应产物核对并更正数量级 |
| 非线性扰动模型被描述为线性实现 | 按实际网络和输入重写设置 |
| 直接与间接路线监督条件不一致 | 撤回总体路线优劣结论，保留具体配置的历史结果 |
| 患者准入通过但部分 PDO 样本未准入 | 同时执行患者、样本白名单；受影响模型重新训练 |
| 全体响应标签参与七药子集筛选 | 降为事后探索；不得继续作为确认性主要面板 |
| 多种子模型与单种子基线配对 | 按对应种子重算；如实报告修复是否改变结论 |
| 跨折常数预测产生伪相关 | 禁止据此计算模型相对均值基线的相关性增益 |
| 融合同时增加指纹和扰动特征 | 分离两类信息贡献，撤回仅归因于扰动的解释 |
| 第二层差异区间跨零被解释为“无害” | 改为未检出明确差异；无等效检验不宣称等效 |
| 增加预测行数被解释为排除样本量不足 | 按独立患者数重新解释 |
| 域分类准确率未与多数类比较 | 增加平衡指标和适当基线 |
| 共享表示重建比值被解释为生物共享信息比例 | 改为特定模型下的诊断量 |
| EXP-030 的弱相关与无效基线差值支持强迁移结论 | 保留绝对观察，撤回不成立的判定链 |
| 通用必需基因识别被等同于患者依赖预测 | 分开任务和结论 |

还须核对缺失基因标准化、目标参考表达构造、显著性判断变量、通路数量、来源研究重叠，以及药物与基因筛选条件。审计发现不能仅限于此表。

### A3. 重写周报

修订 [现有周报](D:/Code/DrugScreenLab/docs/reports/weekly_report_20260920.md)，正文固定为：

1. **本周目标与实际完成工作**。
2. **数据与任务说明**。
3. **主要实验设置和结果**。
4. **问题、限制与修订后的认识**。
5. **下一步工作及启动条件**。

附录保留完整结果、分折统计、计算定义和证据索引。背景、主要发现、详细结果和总结之间不重复同一段解释。审计日期晚于报告周期的内容注明“后续复核更正”，不能写成本周已完成工作。

每项实验采用同一叙述顺序：

> 要回答的问题 → 使用的数据 → 输入与预测目标 → 模型和对照 → 真实结果 → 结果含义 → 尚不能回答的问题。

### A4. 必须补充的数据和基线解释

数据表覆盖实际使用的 GDSC、PRISM、Kryeziu、Zhu、LINCS/ChemPert、DepMap 和类器官依赖资源；CTRP 等仅准备完成的资源单列。

每项说明：来源与版本、实验背景、原始规模、实际使用规模、独立生物样本数、记录单位、输入单位、标签方向、重复测量处理、缺失情况、跨资源身份匹配，以及训练或验证用途。

三类均值基线必须分别定义：

- **来源细胞系药物均值**：仅由来源训练细胞计算；每种药物对所有目标样本给出相同分数。
- **目标类器官药物均值**：仅由当前目标训练折计算；按预定规则先在患者内汇总，再按患者等权计算。
- **目标基因依赖均值**：每个基因在目标训练折中的平均依赖分数；对测试患者给出相同预测。

历史实现若使用其他权重，照实说明，不能把新定义套回旧结果。PRISM 中的来源均值注明来自 GDSC。

### A5. 验收

- 核心数字均能追溯到产物和计算条件。
- 每个比较都能看出双方监督信息、数据和模型差异。
- 没有将准备工作写成实验完成。
- 没有将观察、推断和机制解释混写。
- 周报、状态文件、注册表与实验记录对同一结论表述一致。
- 原记录保留带日期的更正说明，原始预注册不被静默改写。

## 三、工作包 B：数据合同、工程修复与统一评估

### B1. 数据合同

每个正式数据集明确：

- 患者、生物模型、表达样本、药物、基因的身份键及对应关系。
- 来源、版本、校验和、处理代码和实际准入集合。
- 标签语义、方向、单位、处理时间和剂量信息的可用性。
- 重复测量、重复 PDO、重复文库和缺失值处理。
- 训练、验证、测试与只读审计的角色。
- 禁止使用的标签、样本和外部信息。
- 来源与目标之间的身份重叠。
- 使用全部目标表达数据的设置是否属于预先访问整个目标样本组的评估。

Kryeziu 当前以已核验的 **51 位患者、60 个 PDO 样本**作为准入依据。待确认样本继续隔离；实际可用药物观测数由合同重新生成，不把历史审计计数当成新实验结果。

### B2. 划分与预处理

- 所有模型共享同一外层划分和评价记录。
- 同一患者的全部样本放入同一折；细胞系按生物身份隔离。
- 特征筛选、标准化、缺失值处理及学习型参考仅在训练数据拟合。
- 划分种子与模型初始化种子分别记录。
- 默认目标域外层五折、内层三折；不满足有效样本条件时，由 Manager 在看结果前修订合同，执行 Agent 不得静默降折。
- 模型训练前检查每折的独立患者数、药物覆盖和可评价数量。
- 来源 512 特征流程与 2,000 基因消融作为不同配置保留，禁止混写。
- 未准入样本曾进入训练时必须重训；只过滤最终预测不算修复。

### B3. 统一输出与比较检查

预测产物至少包含：

`experiment_id、run_id、contract_id、split_id、fold、seed、patient_id/model_id、sample_id、drug_id/gene_id、y_true、y_pred、model_id、evaluation_role`。

运行元数据记录输入校验和、配置、代码版本、环境、训练及选模信息。存在未提交代码时保存实际差异标识，不能仅记录基础提交号。

比较前必须检查：

- 评价键一致，真实标签一致；
- 同折、同种子或预注册的集成方式一致；
- 候选药物和基因集合一致；
- 没有重复行或缺失模型被静默排除；
- 逐患者权重一致；
- 缺失预测及评价失败有明确记录。

任一检查失败时，停止受影响比较，不自动取“双方交集”继续生成漂亮表格；确需共同集合，必须在协议中定义并报告损失的覆盖范围。

### B4. 指标与统计

**主要药敏指标**：患者内全药物排序 Spearman，按患者等权汇总；主要比较为相对同监督条件均值基线的配对增益。

**辅助指标**：

- 同药物跨患者相关性，按有效折计算。
- 前 1–3 个药物选择质量。
- 实测药物面板内选择损失。
- NDCG@5，明确当前增益定义与局限。
- 同端点域内的误差和校准；跨端点不直接比较原始误差。

默认每位患者至少有三种共同实测药物才计算主排序指标；相关性未定义、标签全相同或药物不足时报告人数与原因，不填零。每个患者先在其重复样本内汇总，避免多样本患者权重更大。

统计要求：

- 以独立患者或细胞为重采样单位，默认 2,000 次。
- 初始化种子描述训练波动，不作为独立生物重复。
- 固定预测的重采样区间与重复训练变化分开报告。
- 多个主要比较使用预注册的 Holm 校正；辅助分析标明探索性质。
- 不以区间跨零证明等效；没有实际效益阈值依据时，不宣称临床实用。
- 报告有效样本数、覆盖范围、点估计和区间，不能只报显著性。

### B5. 必须通过的测试

1. 未准入样本被拒绝，即使其患者已准入。
2. 同患者不跨折。
3. 修改测试标签不改变训练预处理。
4. 整行表达置换在该患者所有药物记录中一致。
5. 多种子模型与基线正确配对。
6. 常数相关性返回未定义及原因。
7. 缺失基因标准化符合合同。
8. 不同药物面板或标签不一致时拒绝比较。
9. 显著性条件使用正确变量。
10. 人工构造的正确排序、随机排序和逐步加噪预测产生合理指标变化。

先做最小完整链路测试，再正式运行。涉及共享模块、数据合同或注册表时，执行完整测试和登记验证。

## 四、工作包 C：补齐来源泛化与迁移证据链

### C1. 四层实验矩阵

| 层级 | 设置 | 回答的问题 |
|---|---|---|
| 同研究未见细胞系 | 来源研究内按身份留出 | 模型能否预测新的细胞系？ |
| 跨研究未见细胞系 | 来源训练，另一研究严格未见身份测试 | 换研究后是否保留能力？ |
| 零目标标签类器官 | 不使用目标药敏标签训练和选模 | 来源知识能否直接迁移？ |
| 少量目标标签类器官 | 相同目标训练患者下比较 | 来源知识能否减少目标标签需求？ |

先复核 EXP-016、EXP-019 的现有产物，再补足未完成条件。当前证据应写为：来源内部有有限信号，跨研究 PRISM 未超过主要简单基线；不能写成“细胞系泛化完全未知”或“已经解决”。

### C2. 公平比较与定位失败阶段

- 各层报告原生药物面板表现，同时增加共同药物面板诊断。
- 同疾病比较控制癌种构成；等样本量比较控制来源训练量。
- 固定一个已选来源模型贯穿跨研究和类器官评估，避免每层换模型后把差异称为迁移损失。
- 每层比较药物均值、药物信息单独模型和表达条件模型。
- 增加癌种内整行表达置换，检验患者信息贡献。
- 同一模型、同一药物面板下仍有端点与平台差异，不能把全部分数下降归因于培养体系。

少量目标标签阶段默认用外层训练患者的 25%、50%、100% 形成嵌套子集；各模型共享子集与测试患者。子集不满足训练或内层验证条件时，记录该档不可评价，不临时改用测试患者。

### C3. 结果判定

需要分别判断：

- 指标对已知变化不敏感；
- 来源模型尚未学到可泛化规律；
- 来源内部有效但跨研究失效；
- 跨研究细胞系有效但类器官迁移失效；
- 目标域有监督模型可学，而来源迁移没有增益；
- 数据不足以区分上述解释。

既有队列已经影响方法选择时，后续属于开发复核。真正的新外部确认须另有未参与选模的数据；不虚构可用独立队列。

## 五、工作包 D：两条路线的能力梯度与公平验证

### D1. 模型梯度

| 层级 | 直接药敏路线 | 扰动介导路线 |
|---|---|---|
| 基础 | 均值、逐药正则化、显式交互模型 | 全局扰动均值、药物单独信息、基础扰动预测 |
| 中等 | 调参后的树模型、小型交互网络 | 条件化非线性扰动模型及药敏预测部分 |
| 较高能力 | 更强的药物—表达交互模型 | 适配输入和标签的预训练扰动模型或受控扩展网络 |

具体高能力外部模型由 Manager 在数据适配审计后选定，每条路线首轮仅一个候选。选择依据包括可复现资产、基因空间、监督标签、显存、预训练重叠和官方实现，不按目标测试分数选模型。

现有 XPert、TranSiGen 等资产先核查可复用程度，不能因为模型名称出现在旧方案就默认适用，也不能未经检查重新造轮子。

### D2. 调参与资源约束

- 首轮每个可调模型最多 20 个内层候选配置。
- 深度模型最终配置默认三个初始化种子；确定性模型不制造重复运行。
- 测试集不参与早停、配置选择或候选模型筛选。
- 训练前登记参数量、搜索空间、最大训练步数、早停规则和总预算。
- 按 RTX A5000 24 GB 设计单 GPU 方案，执行前核实设备。
- 显存不足时不得静默删样本、缩基因集、改药物面板或缩短正式训练。先记录问题；保持数学目标不变的工程修复可进行，改变研究设置须修订协议。
- 基础模型失败仍允许一次受控高能力诊断；无验证收益后不得无限增加模型和种子。

### D3. 分离监督、预处理和预训练收益

少量目标标签下至少区分：

1. 目标数据从头训练；
2. 来源预处理加随机初始化；
3. 来源预训练权重迁移；
4. 扰动特征加目标药敏监督。

零目标标签下，直接与间接路线的来源药敏监督应匹配。纯逆转评分单列为无目标标签的机制基线，不与有目标监督模型的差值直接解释成路线优劣。

上游扰动任务单独评价：

- 已见与未见化合物分别报告；
- 明确 ChemPert 与 LINCS 的来源重叠；
- 稀疏上下调标签不视为完整连续变化；
- 剂量、时间未建模时明确边界；
- 覆盖率不足作为待检验解释，不预设是主要原因；
- 基于全体目标样本均值的参考属于特定目标访问设置，不称为肿瘤—正常差异。

## 六、工作包 E：重新设计融合实验

### E1. 串联架构

**基线表达＋药物 → 扰动表示 → 药敏预测。**

先冻结扰动模型训练下游药敏部分，再测试联合微调。当前标签若只支持方向性扰动表示，使用该表示；只有连续表达变化与基线量纲兼容时，才构造处理后表达。

必须比较：

- 不使用扰动；
- 使用预测扰动；
- 使用打乱扰动；
- 使用维度、容量相近的普通学习特征。

确有同样本、同处理条件的实测扰动时，增加实测扰动参考；没有就明确无法检验这项参考。

### E2. 并联架构

**直接表达—药物分支＋扰动分支 → 药敏预测。**

从低维、正则化的组合开始，再测试条件化权重。对照包括两条单分支、双分支、参数量相近的直接模型，以及打乱扰动分支。

药物指纹增量与扰动增量分别检验，至少包含：

- 直接预测；
- 直接预测＋药物指纹；
- 直接预测＋扰动；
- 直接预测＋指纹＋扰动。

### E3. 联合学习

使用部分共享表示，同时学习药敏和扰动任务。

- 对实际存在的标签计算损失；缺失标签不填零。
- 不假设不同数据集天然逐样本配对。
- 辅助任务权重仅由训练、内层验证选择。
- 检查辅助任务改善是否来自额外数据或参数量。

三种架构分别登记，一次只改变一个关键因素。第二层融合需要训练集内部的折外预测；不能用外层测试预测或标签拟合融合器。

旧拼接结果保留为特定设计的负结果。弱上游表现不自动禁止一次受控融合诊断，但后续扩展需要相对匹配对照的稳定增量。

## 七、工作包 F：同疾病域差异与基因依赖能力分析

### F1. 控制疾病构成的域差异分析

主要比较设为同癌种细胞系与类器官，并配套：

- 泛癌来源与同癌种来源；
- 等来源样本量；
- 同癌种跨研究细胞系；
- 统一基因与表达处理；
- 患者或细胞分组的留出检验。

分析内容包括分布距离、最近邻、域分类、表示重建和预测误差关系。

约束：

- 域分类报告平衡准确率及置换基线。
- 表示重建比例只解释为该模型下的结果。
- 距离与误差无明确关联时，不宣称距离导致失败。
- 同癌种样本不足时报告不确定性，不反复切分直到出现显著结果。
- 疾病、平台和培养体系完全混杂时，明确无法独立识别原因。
- 通路与机制分析控制多重比较，并在留出数据验证。

### F2. 重建基因依赖评价

分别评价：

1. 通用必需基因识别；
2. 癌种或谱系依赖；
3. 同癌种、同一基因在不同患者之间的依赖变化。

第三项是个体化能力的核心。保留逐基因折内相关性，增加患者整体置换和癌种控制；不再减去未定义的基因均值相关性。

明确来源 Chronos 与目标文库处理标签的区别。目标域训练模型只称“目标域参考模型”，不称上限。正斜率仿射校准通常不改变排序，校准效果应使用适合其目标的指标。

### F3. 归纳偏置与学习曲线

对比：

- 逐基因独立正则化模型；
- 低秩多任务模型；
- 非线性共享表示；
- 固定通路结构模型及等规模随机分组对照。

使用相同输入、患者划分、搜索预算及训练量档位，报告训练和验证表现：

| 观察 | 允许的解释 |
|---|---|
| 训练与验证均差 | 检查优化、输入信息和模型表达能力 |
| 训练好、验证差 | 检查过拟合、样本量和分布变化 |
| 域内好、跨域差 | 检查跨域端点与表示问题 |
| 更强模型稳定改善 | 支持旧模型能力不足 |
| 多模型均弱 | 说明当前条件下未获得强预测，不足以证明数据不存在规律 |

只有可比的重复测量支持时才估计测量可靠性与噪声限制。否则交付“当前输入和模型家族下的可达表现参照”，不写数值上限。

候选可迁移基因、通路与依赖图谱全部在训练侧选择，在留出患者上验证。若后续用于药敏任务，检查患者重叠并在相应训练折内重新生成。

## 八、工作包 G：项目与文档规范

### G1. 明确文档职责，避免多个“当前方案”

沿用现有目录，不另建一套平行文档体系：

| 文档类型 | 唯一职责 | 不应承载的内容 |
|---|---|---|
| `AGENTS.md` | 长期工作原则、权限和协作边界 | 当前模型冠军、具体实验数字 |
| 项目状态与注册表 | 当前状态、实验索引、有效结论摘要 | 长篇实验过程 |
| 主研究方案 | 研究问题、路线、长期目标 | 每次运行日志 |
| 当前执行计划 | 阶段顺序、任务包、验收与依赖 | 重复复制全部结果 |
| 实验记录 | 假设、批准协议、执行偏差、最终结果及证据入口 | 多个不一致的最终版本 |
| 专题技术报告 | 必要的详细分析 | 重复另一报告的完整正文 |
| 周报 | 本周期进展、关键结果、问题与下一步 | 日志堆砌、无解释缩写 |
| 运行产物与日志 | 精确执行事实 | 代替面向读者的解释 |

建立一个文档导航入口，链接当前有效方案、最近报告、数据说明和实验记录。旧方案注明“历史”“已替代”及替代链接；不删除研究历史，不让执行 Agent 从多个冲突文件中自行挑选方便的规则。

### G2. 统一并清理规则冲突

当前治理文档与长期规则存在粒度和编排方式差异，需统一：

- 工程修复、只读审计与正式研究的边界；
- 正式训练和评测的批准入口；
- Agent 角色、模型选择与实际运行能力；
- 原有“有信号才扩展”与本方案“允许一次受控容量诊断”的关系；
- 文档状态及实验验收流程。

长期规则写入长期文档，本轮特例留在执行计划和实验协议。不能通过改规则绕过既有批准边界。

### G3. 写作要求

每份面向用户的报告必须做到：

- 标题直接说明研究问题。
- 开头给出当前结论与完成状态。
- 术语、缩写首次出现即解释；优先使用中文任务名，再附 EXP 编号。
- 数字同时说明对象、方向、单位、样本量、比较对象与意义。
- 数据规模区分患者、模型、记录及重复测量。
- 结果与解释分段，机制假设明确标注。
- 一个结论集中解释一次，其他位置引用。
- 主结果表不混用不同面板、监督条件和统计口径。
- 日期、版本、状态与证据入口清楚。
- 不以“全面验证”“明确证明”“上限”“不可行”等词替代证据。

例如：

> “同一划分的三个初始化均改善”可以支持初始化稳定性；不能改写为“三次独立实验确认可迁移”。

### G4. 文档模板和验收

统一实验报告模板：

1. 研究问题与预先假设；
2. 数据背景及实际使用范围；
3. 输入、标签、划分和模型；
4. 基线、主要比较及指标；
5. 结果表；
6. 解释、限制与失败分析；
7. 下一步决策；
8. 复现与证据索引。

文档检查分两层：

- **自动检查**：必要栏目、状态、链接、产物引用、结果表必需字段、引用数字与紧凑指标一致性。
- **人工审查**：能否不依赖聊天上下文理解任务；比较是否公平；结论是否超过证据；是否存在重复和未解释术语。

自动检查不能代替逻辑审查。数字来源尽量集中到紧凑指标文件，避免手工维护多份结果表。

### G5. 文件与版本管理

- 先盘点当前未提交及未跟踪文件，不覆盖用户已有工作。
- 新工作在明确分支或隔离工作区进行；只带入有清单和版本标识的必要资产。
- 大矩阵、预测、模型和日志不进入 Git；登记路径、版本、校验和与生成命令。
- 不批量删除旧文档。先建立引用和替代关系，再按项目规则归档。
- 不使用多个“最终版、最终修正版、最终完整版”作为并行入口；一个有效版本配变更记录。
- 既有 EXP 编号先核查注册表、记录和占位文件，不直接覆盖看似空白或未完成的记录。

## 九、执行 Agent 的任务合同与验收机制

### 1. 分工

Manager 负责科学设计、实验范围、关键选择、证据合并与最终判断。执行 Agent 负责已明确的代码、数据处理、测试或文档工作，不自行决定研究方向。

沿用项目约定的 Sol Manager、Terra Executor 编排；当前会话模型不符合该角色配置时须如实说明，不能宣称已按该模型编排运行。角色仅代表职责，实际启动的 Agent 和审查才可记录为已完成。

独立审查与实现分离；没有独立审查条件时，结果注明“尚未独立审查”，不伪造 Reviewer。

### 2. 每个任务包必须包含

| 项目 | 内容 |
|---|---|
| 目标 | 一个明确可验收的问题 |
| 输入 | 文件、合同、配置与版本 |
| 允许修改 | 精确目录、模块或文档 |
| 禁止修改 | 数据角色、划分、主要指标、标签、测试集等 |
| 执行步骤 | 顺序、依赖、命令入口 |
| 产物 | 文件、格式与必要字段 |
| 验收 | 测试、数值核查及文字要求 |
| 失败条件 | 哪些情况停止当前任务并上报 |
| 资源 | GPU、内存、运行次数和预算 |
| 状态回执 | 完成、未完成、阻断、偏差和证据 |

禁止发出“把结果做好”“试更多模型”“分析一下有没有规律”等无边界任务。

### 3. 执行 Agent 不得擅自采取的行为

- 改主要指标、药物面板、准入条件或外部测试角色。
- 为改善结果删除患者、基因或药物。
- 根据测试结果选模型、阈值、特征或参考表达。
- 混合不同种子、不同折或不同候选集合后计算增益。
- 在失败后静默改用更小样本并报告成功。
- 把运行完成当作有效结果，把准备工作当作实验完成。
- 将弱相关、接近的点估计或跨零区间解释成稳定规律、上限或等效。
- 未经适配检查引入新模型、新数据和依赖环境。
- 使用 Windows Python 或临时创建环境。
- 批量覆盖文档、删除历史或重写原预注册。

发现合同无法执行时，上报具体冲突及受影响范围；其他独立、已授权任务可继续。

### 4. 状态与发布

“运行完成”“证据有效”“支持假设”分别记录。科学结果至少区分：

- 支持预先假设；
- 不支持预先假设；
- 证据不足；
- 实验无效。

执行 Agent 提交产物与自检；Manager 复核关键输入、测试、指标和表述，再进入独立审查。用户报告仅引用通过相应检查的结果。

## 十、实施顺序与最终交付

| 阶段 | 工作 | 启动条件 | 验收产物 |
|---|---|---|---|
| 0 | 工作区、证据及文档盘点 | 当前状态可读取 | 资产清单、冲突和缺口表 |
| 1 | 历史审计与周报修订 | 数字和产物可追溯 | 修订周报、证据表、更正记录 |
| 2 | 数据与评估工程修复 | 问题定位完成 | 合同、统一接口、测试结果 |
| 3 | 正式实验预注册 | 工程检查通过 | 模型与比较矩阵、预算、失败条件 |
| 4 | 来源泛化、迁移与容量诊断 | 对应实验获批 | 配对预测、统计结果、阶段判断 |
| 5 | 串联、并联与联合学习 | 对应接口和数据可用、实验获批 | 归因清楚的融合结果 |
| 6 | 同疾病差异与依赖任务 | 身份、标签及评价修复完成 | 控制分析、学习曲线、候选规律 |
| 7 | 综合复核与后续决策 | 证据包完整 | 结论报告、更新状态、外部验证条件 |

文档治理贯穿所有阶段。来源模型与扰动上游可在合同稳定后并行，基因依赖任务可独立推进；不为并行而拆分，不让整套研究被无关任务阻塞。

最终交付包括：

1. 一份准确、精简但背景充分的周报。
2. 一份逐项可追溯的实验审计与结论更正表。
3. 一套通过测试的数据准入、划分和评估流程。
4. 一组监督条件清楚、模型能力分层、统计配对正确的复核实验。
5. 一份能够区分泛化、迁移、模型能力、数据和测量限制的综合报告。
6. 一套统一的项目文档入口、模板、状态规则和 Agent 任务合同。

本方案的完成标准是：后续读者和执行 Agent 无须猜测内部上下文，就能理解每个实验为何进行、如何执行、什么结果支持或反对假设，以及结论可以用到哪里。
