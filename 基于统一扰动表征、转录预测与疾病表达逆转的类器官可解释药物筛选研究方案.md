# 基于统一扰动表征、转录预测与疾病表达逆转的类器官可解释药物筛选研究方案

## 1. 项目定位

本项目拟建立一个以**转录扰动预测和疾病状态逆转**为核心的计算药物筛选体系。

最终主线为：

**大规模 chemical/genetic perturbation 数据 → 条件化转录扰动预测 → 疾病表达签名构建 → 表达/通路逆转 → 细胞系药效验证 → 类器官机制迁移 → 类器官药物排序。**

项目不是直接学习：

`SMILES + disease RNA → IC50`

而是明确区分三个层次：

```text
扰动机制
    ↓
药物在当前 biological context 中造成什么转录变化
    ↓
这种变化能否逆转疾病状态
    ↓
这种逆转是否最终对应真实药效
```

这与已有 CMap、TranSiGen、PRnet、XPert、MultiDCP、UniPert-G2CP、OCTAD 等工作的共同发展方向一致：药物作用不是一个 context-independent 的固定向量，而是 perturbagen 与 biological context 共同决定的状态变化；疾病筛选则建立在疾病与药物转录状态的反向匹配基础之上。

---

# 2. 整体科学假设

整个项目采用一个已经有大量前人证据支持的基本关系：

```text
Perturbagen mechanism
        ×
Biological context
        ×
Dose / Time
        ↓
Transcriptional perturbation
        ↓
Disease reversal
        ↓
Drug efficacy probability
```

其中：

- **Perturbagen** 不仅包括 chemical drug，也包括 CRISPRi、CRISPRa、KO、OE 等 genetic perturbation；
- **Context** 是扰动前细胞、组织或类器官的真实状态；
- **Perturbation** 首先以 978 landmark genes 为最高可信度核心；
- 非-landmark genes 只能通过真实 WTS 数据或经独立 WTS 验证的扩基因模型进入；
- Pathway 是连接细胞系和类器官的重要机制层；
- phenotype screen 用于验证“逆转是否等于药效”。

用户提供的研究资料也已经形成了相同的总体认识：不同公共数据提供的是不同种类监督，不能简单拼成一个矩阵；类器官阶段应“共享机制，不强制共享最终表达结果”。

# 4. 978 landmark genes 是不可替代的核心

本项目明确规定：

**978 landmark genes 永远是 perturbation prediction 的 Core Gene Space。**

原因不是方便，而是数据证据等级。

LINCS GSE92742 包含超过 130 万条 L1000 perturbational profiles；L1000 的实验体系直接测量 landmark transcripts，而其它基因空间涉及 inference。GSE92742 和 Phase II GSE70138 均已由 GEO 公开。

XPert 2026 同样把 978 landmark transcriptional changes 作为正式预测目标，使用 Level-3 treatment/control profiles，并使用同 plate DMSO 构造 pre/post pairs。

因此系统始终保留：

**Δ978 prediction**

以及：

**978-specific disease reversal score。**

扩基因不能替代这一层。

---

# 5. UniPert-G2CP：从辅助 embedding 提升为核心机制桥梁

这里需要对前面方案做重要修正。

UniPert-G2CP 最重要的价值并不是：

> “又多一个 drug embedding。”

而是：

> **把 chemical perturbagens 和 genetic perturbagens 映射到统一 perturbagen representation space。**

Cell 2026 的正式工作明确把 genetic 和 chemical perturbagens 放到共享空间，并通过 genetic-to-chemical transfer 改进 perturbation phenotype modelling 和 generalization。

这对于类器官尤其重要。

因为现实的数据结构是：

```text
Cell line
chemical perturbation data       很多

Organoid
chemical perturbation RNA data   很少

Organoid
genetic perturbation data        相对可获得
```

所以应该利用：

```text
Chemical drug
      ↓
 UniPert chemical representation
      ↘
       Shared Perturbagen Space
      ↗
CRISPRi / CRISPRa / KO
      ↓
 UniPert genetic representation
```

然后学习：

```text
Perturbagen Space × Context
            ↓
      Transcriptional Response
```

因此 organoid genetic perturbation 不再只是“机制解释数据”。

它承担一个非常实际的任务：

> **在缺少大规模 organoid chemical perturbation RNA 的情况下，帮助模型学习类器官中 perturbation mechanism 如何传播为 downstream transcriptional response。**

这与用户已有 OrganoPert 文档中 chemical↔genetic perturbation 作为 Drug→Target 桥梁的设计是一致的。

但仍然保持一个安全边界：

**chemical→genetic transfer 在 organoid domain 的实际收益必须通过 held-out chemical/organoid evidence 验证，不能因为 UniPert 在其它数据上成功就自动假定其一定成功。**

---

# 6. Core Perturbation Model：直接站在 XPert 等工作基础上

不重新设计一种完全新的深度网络。

主架构采用 **XPert-style biologically informed dual-branch transformer** 作为最主要的方法学基础。

XPert 已经正式证明：

```text
Pre-perturbation expression
+
Drug representation
+
Dose
+
Time
→
ΔExpression
+
Post-treatment expression
```

并且在 cold-drug、cold-cell 和 multi-dose/multi-time 条件中进行了系统评价；其 preprocessing、训练、评价代码以及处理数据均公开。

其设计本身非常符合本项目归纳偏置：

- base branch 学 biological context；
- perturbation branch 学 cell×drug interaction；
- gene token 保留 gene identity/network information；
- chemical/biological drug information分开表示；
- dose/time 显式建模。

---

# 7. 对 XPert 的最小必要扩展

本项目不从头重新造 backbone。

只对 perturbagen representation 做一项与任务直接相关的改造：

XPert 原本主要针对 chemical perturbation。

本项目将 perturbagen token 扩展为：

```text
Chemical perturbagen
→ UniPert chemical embedding

Genetic perturbagen
→ UniPert genetic embedding
```

它们进入同一个 context-conditioned perturbation backbone。

化学结构信息仍可保留 XPert 已经采用的 pretrained molecular representation；UniPert 则负责提供跨 chemical/genetic modality 的共享 mechanism coordinate。XPert 已经证明 multiscale drug representation + context modelling 可行，UniPert则证明了 unified genetic/chemical cause representation 可行。

这是本项目真正的“集成创新点”之一，但不是凭空构造两个从未验证过的网络。

它是：

**XPert 的 conditional response architecture**

+

**UniPert 的 unified perturbagen representation**

的任务驱动组合。

# 8. PRnet、TranSiGen、MultiDCP 的角色

它们不是全部塞进最终网络。

### PRnet

作为：

- pretrained/reference conditional perturbation model；
- unseen compound baseline；
- virtual screening baseline。

PRnet已经实现 `unperturbed transcriptome + chemical structure → perturbation`，并公开 LINCS、sci-Plex preprocessing 和代码，还进行了 SCLC/CRC 实验筛选。

但其 978→12,328 的线性 expansion 不进入本项目正式 gene expansion。PRnet Methods明确使用固定 L1000 linear transformation 完成这一扩展。

### TranSiGen

作为：

- perturbation denoising/reference latent；
- CMap-style disease screening baseline。

不重新训练第二套平行生产系统。

### MultiDCP

它的重要价值是已经直接证明：

```text
Drug
+
Basal context
+
Gene representation
+
Dose
→
Gene-specific perturbation
```

这一因子化建模方式可行，并在 leave-new-cell-out 场景评估 context generalization。

因此它是后面扩基因模块最重要的独立方法依据之一。

# 9. Reliable Gene Expansion：978 之上的增强层

最终 gene space 分为两个严格不同等级：

```text
G_core = 978 landmark genes

G_extended =
经过真实 WTS supervision
或者
经过独立 WTS calibration
证明可预测的非-landmark genes
```

禁止：

```text
predicted 978
→ fixed inference matrix
→ 10k genes
→ 全部当成可信 perturbation
```

# 10. 扩基因采用“前人已有方法的组合”，而不是重新臆想

扩基因模块建立在两个已有经验之上：

### MultiDCP / DeepCE

证明：

**gene representation 本身可以进入 drug-induced expression prediction。**

MultiDCP使用 gene network embedding、drug、basal context 和 dose 联合预测 gene-specific response。

### GPS

借用：

**gene-feature generalization + independent whole-transcriptome calibration**

这一方法思想。

但由于 GPS 结果复现存在风险：

- 不依赖 GPS checkpoint；
- 不使用其最终 gene list；
- 不复用其性能数字。

最终由我们自己的公开 WTS 数据决定哪些 genes 能进入 G_extended。

---

# 11. Whole-transcriptome 数据怎样使用

首先使用 **sci-Plex3** 作为非-landmark gene 的直接实验监督。

sci-Plex3公开测量 A549、MCF7、K562 经 188 个 compounds、多个剂量处理后的 single-cell whole-transcriptome profiles，并公开 count matrix、annotations 和 processed RDS。

因此：

```text
LINCS
→ 大规模 compounds / contexts
→ 强监督 978

sci-Plex
→ compounds 数较少
→ 真实 whole-transcriptome supervision
```

共同训练。

# 12. 独立 WTS Calibration

至少保留一个完全不参与 gene-expansion fitting 的 WTS dataset。

推荐主数据：

**PANACEA / GSE186341**

包含 11 个 cancer cell lines、32 个 kinase inhibitors、1,728 RNA-seq profiles，并有 DMSO/untreated controls；数据公开于 GEO。

第二个外部 calibration：

**DRP006006**

公开 SRA 数据包含 23 个 lung cancer cell lines、95 compounds、3,240 RNA-seq 和 3,393 ATAC-seq datasets，并包含多剂量/多时间和跨细胞系设计。

于是流程是：

```text
LINCS + sci-Plex
      ↓
Train extended-gene predictor
      ↓
Freeze
      ↓
PANACEA / DRP006006
      ↓
Per-gene validation
      ↓
G_extended
```

# 13. Disease Signature：必须作为独立的生物信息学模块

这是前面方案不足最大的部分之一。

疾病表达谱不是“完整 RNA 全部扔进去”。

经典 transcriptional reversal 通常先构建：

```text
Disease-up genes
Disease-down genes
```

再与 drug-induced ranked gene profile进行 GSEA/KS-style connectivity matching。系统性 connectivity-score 研究也明确把 disease signature 定义为疾病显著 up/down genes 与 ranked drug profile 之间的关系。

---

# 14. Disease Signature 到底应该多大

**没有一个固定数字。**

它可能是几十、几百，也可能数千个。

取决于：

- disease effect strength；
- sample size；
- tissue heterogeneity；
- sequencing depth；
- statistical threshold。

例如 Chen 等人在 Nature Communications 的 cancer reversal 工作中，对 tumor vs normal 使用：

**|log2FC| > 1.5 且 adjusted P < 0.001**

定义 disease signature，并进一步证明 cancer-expression reversal 与 preclinical drug efficacy 存在相关性。

另一个 personalized ccRCC connectivity研究发现，在其评估设置中，使用 **1% FDR 筛选的 tumor genes，再结合 log2 fold difference** 获得较低的假阳性。

因此正式方案不规定：

> disease signature = 978 genes

也不规定：

> disease signature = 2,000 genes。

---

# 15. Cohort-level Disease Signature

如果存在多例 Disease 与 Normal：

### RNA-seq

使用成熟的：

- DESeq2；
- edgeR；
- limma-voom。

OCTAD 的公开 protocol 同样建立在标准 RNA-seq differential-expression pipeline 和 cancer-specific normal reference 上。

首先产生：

```text
gene
log2FC
P value
adjusted P
```

Primary disease signature使用：

```text
FDR threshold
+
minimum |log2FC|
```

同时保留完整 ranked log2FC vector。

为什么两套都留？

因为：

- 显著 DEG 集合适合经典 CMap reversal；
- full ranked list 适合 pathway/GSEA；
- 可以测试不同 signature cutoffs 的稳定性。

阈值不人工迷信某一个数字，而是在 development cancers 中预先选择，然后冻结。

---

# 16. Personalized / 单个 PDO Disease Signature

如果只有：

**单个 tumor PDO**

和：

**normal reference cohort**

不能简单把一个样本当成一个统计组计算普通 p-value。

可以借鉴 MultiDCP 已经实际使用过的 personalized differential-expression 思路。该工作使用患者 basal expression，并通过 PENDA 产生 patient-specific up/down disease signatures，再进行 patient-specific drug reversal。

因此分两类：

### 有 matched normal PDO

直接计算 patient-specific effect size，并结合 reference normal variance。

### 没有 matched normal

使用 same-tissue normal-organoid cohort 建立 reference distribution，再得到 sample-specific dysregulated genes。

---

# 17. Disease Signature 与 978 不一致怎么办

这是正常情况，不是异常。

假设 Disease Signature 有 3,000 个 genes。

其中：

```text
3000 disease genes
      │
      ├─ 180 与 978 core 相交
      │
      ├─ 900 属于可靠 extended genes
      │
      └─ 其余通过 pathway 表达
```

于是疾病信息不会因为 L1000 只有 978 而被强行裁掉。

建立三个并行 scoring channels：

### Landmark Reversal

```text
Disease DEG ∩ 978
```

最高可信。

### Extended Reversal

```text
Disease DEG ∩ G_extended
```

按照 gene reliability 加权。

### Pathway Rescue

使用完整 disease expression 获得 pathway abnormality，再与 predicted drug pathway response 比较。

---

# 18. 缺失基因问题

必须区分：

**0 expression**

和：

**assay 根本没有测这个 gene。**

RNA-seq 中的 zero count 通常不是“缺失”。

真正的 missing gene 常见于：

- microarray probe coverage；
- feature filtering；
- gene-ID mapping failure；
-低质量测序。

正式策略不是盲目 imputation。

定义：

```text
G_disease_measured
G_context_measured
G_core
G_extended
```

逆转永远只在真实 overlap 上计算：

```text
G_score =
G_disease_measured
∩
G_drug_reliable
```

并报告：

**Gene Coverage Ratio。**

如果 signature coverage 太低，模型应降置信度，而不是创造不存在的表达值。

---

# 19. 最关键的问题：Disease state 与 LINCS DMSO 分布不同怎么办

这里必须把两件事情彻底分开：

## Disease Signature Branch

负责回答：

> 疾病相对于正常，哪里异常？

它只参与 reversal。

## Perturbation Context Branch

负责回答：

> 当前这个细胞/类器官在给药前是什么状态？

它进入 perturbation model。

**不能把 disease DEG signature 直接当作 LINCS DMSO expression 输入。**

---

# 20. Target Context 的跨平台处理

LINCS DMSO 是 L1000 normalized expression。

目标 PDO 通常是 RNA-seq。

因此不能直接把 raw TPM/count 与 L1000 数值拼在一起。

XPert 在跨数据集处理中使用 gene-token + binned relative expression，并明确提出对于新数据集应重新计算 bin boundaries，以降低不同 sequencing protocols 的绝对量纲差异；同时它还展示了 L1000 pretraining 后向独立 preclinical/clinical datasets transfer 的能力。

因此 Context 输入采用：

```text
RNA-seq
↓
gene ID harmonization
↓
extract 978 landmarks
↓
within-dataset normalization
↓
rank/bin relative expression representation
↓
context encoder
```

而不是：

```text
TPM
→ 强行变成 LINCS z-score
```

---

# 21. 对真正 OOD 的疾病/PDO不能假装解决

在 inference 前计算：

**Context OOD score。**

比较目标样本与训练 untreated/DMSO contexts 在 context latent 中的距离。

若目标样本位于已验证 domain：

→ personalized perturbation prediction。

若严重 OOD：

→ 输出低可信警告。

极端情况下：

→ 不进行 patient-specific perturbation prediction，退回 lineage/reference-context screening。

这是整个系统必须具备的 **abstention mechanism**。

---

# 22. 为什么 PrePR-CT 在这里值得采用

PrePR-CT 的重要贡献是：

**不需要 target context 已经拥有大量 drug labels。**

它利用 untreated target cells 构建 cell-type-specific co-expression network，在 small-data 和 unseen-cell-type 场景中帮助预测 chemical perturbation。

所以类器官侧可以利用：

```text
大量 untreated organoid cells/samples
         ↓
Context-specific co-expression prior
         ↓
Organoid context representation
```

这解决的是：

**DMSO cell-line context ≠ organoid context**

而不是简单用 adversarial alignment把两个 domain 硬拉到一起。

# 24. 数据清洗原则

## Compound

在任何 split 以前完成：

- canonical SMILES；
- salts；
- stereochemistry；
- aliases；
- PubChem/ChEMBL/CMap ID；
- duplicate structure collapse。

否则 identical/nearly identical compounds 会跨 train/test 泄漏。用户提供的研究文档也已经明确强调这一点。

## Transcriptome

drug perturbation 使用：

```text
treated − matched control
```

control 匹配：

- cell；
- batch；
- plate；
- time；
- treatment condition。

XPert同样按同 plate DMSO 建立 paired pre/post profiles。

## Single-cell

用于主监督时：

```text
cell
↓
metacell / pseudobulk
↓
perturbation × donor/context
```

不把 10 万 cells 当成 10 万 biological replicates。

# 30. Phase VI — 先做细胞系筛药闭环

这是本次方案最重要的验证顺序修正。

**在任何 organoid generalization 声明以前，模型必须首先证明自己在 cell line 世界里会筛药。**

原因很简单：

cell-line perturbation、basal RNA、drug phenotype 数据都更丰富。

如果在：

**LINCS → cancer cell line → PRISM/CTRP/GDSC**

这一层都不能把真正敏感药物排到前面，就没有理由继续声称模型能迁移到数据更少、domain shift 更大的 PDO。

---

# 31. Cell-line Screening Benchmark

以 cancer lineage 为单位构建 disease signature。

例如：

```text
CRC tumor vs normal
↓
CRC disease signature
```

对于每个 CRC cell line：

```text
其 basal context
+
候选 drug library
↓
predicted drug perturbation
↓
disease reversal score
↓
drug ranking
```

再比较该 cell line 的真实：

- PRISM viability；
- CTRP AUC；
- GDSC IC50/AUC。

2017 年 Nature Communications 已直接证明 cancer-expression reversal 与 breast、liver、colon preclinical drug efficacy 存在关联，因此这个评价链有明确前人经验。

---

# 32. Cell-line 筛药指标

不能只算一次 Pearson。

每一个 cell line 分别评价：

### Continuous

- Spearman(rank, drug sensitivity)；
- Kendall rank correlation。

### Top-K screening

- NDCG@10 / 20 / 50；
- Recall@K；
- HitRate@K；
- sensitive-drug enrichment。

### Classification

将最敏感药物定义成 positive：

- AUROC；
- AUPRC。

Top-K metrics 比全库平均相关更接近真正 virtual screening 任务。

---

# 33. Cross-study 是硬性要求

例如：

```text
PRISM
→ 调 ranking/calibration parameters

GDSC
→ 完全冻结 external test
```

然后反过来：

```text
CTRP
→ development

PRISM
→ test
```

不同 drug-response studies 的绝对 IC50/AUC 不直接混合。

主要比较：

**study-internal ranks / sensitive labels。**

DrEval 2026 对多个公开 cancer drug-response datasets 的系统评价再次表明，随机划分和 drug/cell mean effects 可以严重夸大模型能力，而 unseen-drug、cross-study 和 biologically meaningful splits 才能真正检查 generalization。

---

# 34. Cell-line Go/No-Go

只有以下条件同时成立才进入 organoid stage：

**Gate A**

Δ978 unseen-drug/context prediction可靠。

**Gate B**

Disease reversal 能在 cell-line phenotype screens 中富集 sensitive drugs。

**Gate C**

这种 enrichment 在独立 PRISM/CTRP/GDSC study 中仍存在。

否则：

**停止 organoid transfer。**

这条非常关键。

# 38. Pathway 层

Pathway 不再强制设计成复杂 learned bottleneck。

- disease full RNA；
- predicted reliable drug genes；

计算：

- Reactome；
- GO；

的 pathway activities/enrichment。

同时建立：

```text

↓

↓

↓

```

target-proximal pathway evidence。

已有 organoid pharmacogenomic工作已经证明 known target + STRING + target-proximal pathway representation 对患者/类器官药物反应具有实际价值，因此这一层具有直接经验依据。

---

# 39. Drug Ranking 采用分层而非黑盒

每个 drug 至少有四类结果。

### S1 — Landmark Reversal

最高可信。

### S2 — Reliable Extended Reversal

扩大 disease coverage。

### S3 — Pathway Rescue

增加 mechanism/context robustness。

### S4 — Mechanism Support

Target/network/genetic evidence。

初期使用 rank aggregation。

不要一开始训练一个大网络把所有信息压成一个不可解释 score。

---

# 40. Cell-line phenotype 可以学习“什么样的逆转更有效”

由于 PRISM、CTRP、GDSC 数据很多，可以在 cell-line stage 学一个**低容量 ranking calibrator**：

输入：

```text
Landmark reversal
Extended reversal
Pathway rescue
Mechanism consistency
Chemical OOD
Context OOD
```

输出：

```text
probability/rank of sensitivity
```

模型优先：

- logistic/ordinal regression；
- GAM；
- GBDT；
- pairwise ranker。

这不是重新做：

`SMILES + RNA → IC50`

因为模型看不到 raw structure/raw transcriptome。

它只学习：

> 哪种 molecular rescue pattern 更可能对应真实药效？

# 45. 最终失败保护机制

这套体系不是“一处失败全盘失败”。

如果 gene expansion 不可靠：

→ 保留 978 + pathway。

如果 genetic→chemical organoid transfer 无收益：

→ 删除 UniPert transfer loss，但保留 chemical perturbation model。

如果 target/pathway evidence 不改善排序：

→ 保留为解释，不进入排名。

如果 phenotype calibrator 只在 PRISM 内有效、跨 GDSC 崩溃：

→ 不使用 phenotype calibrator。

如果 organoid context 严重 OOD：

→ 不提供假装精确的 personalized ranking，而是明确标记 exploratory。

# 46. 这项工作的真正创新位置

本项目的价值不应该宣传为：

> “我们设计了一个新的 Transformer。”

真正贡献应该是：

### 第一

**将成熟的 chemical perturbation prediction 与 UniPert chemical/genetic unified perturbagen space结合，使丰富的 genetic perturbation 数据能够为缺少 chemical transcriptomic labels 的 organoid domain 提供机制监督。**

### 第二

**建立 978 measured-landmark core + independently calibrated extended genes 的分级可信 perturbation system，避免传统 inferred whole transcriptome 的误差扩散。**

### 第三

**把 disease-signature bioinformatics、perturbation modelling、mechanistic pathway analysis 和真实 pharmacogenomic efficacy validation真正连接为一个闭环。**

### 第四

**建立严格的 cell-line → cross-study → organoid evidence ladder，而不是直接拿 PDO 做一个小规模 final correlation。**

# 47. 最终项目定义

本项目不是发明一个孤立的新算法，而是一个以现有高水平研究成果为基础的**机制约束、数据驱动、跨扰动模态、跨 biological context 的转录组药物筛选系统**。

它以：

**LINCS 978 landmark perturbation data**

作为最可靠的数据底座；

以：

**XPert-style context-conditioned perturbation modelling**

作为核心转录预测架构；

以：

**UniPert-G2CP unified genetic/chemical perturbagen representation**

连接 chemical 和 genetic interventions，重点解决类器官 chemical perturbation 数据不足；

以：

**MultiDCP/DeepCE/GPS-style gene-aware modelling + independent WTS calibration**

扩展可信 gene coverage；

以：

**DESeq2/limma/PENDA/OCTAD-style disease-signature construction**

处理 cohort 和 personalized disease states；

以：

**CMap/GSEA-style reversal**

完成疾病导向药物排序；

首先以：

**PRISM + CTRP + GDSC**

检验筛药算法在数据丰富的 cancer cell-line domain 是否真正有效；

只有通过这一层以后，才利用：

**GSE280506、GSE145308 等 organoid genetic perturbation**

进行类器官 context/mechanism adaptation；

最后通过：

**GSE117548、GSE64392 等 PDO phenotype resources**

完成真正的类器官外部验证。

最终系统回答的不是：

> “这个模型能不能把表达矩阵预测得很像？”

而是：

> **“面对一个新的疾病 biological context，能否可靠预测候选药物造成的分子扰动，判断它是否逆转疾病状态，并在从细胞系到类器官的独立实验数据中，把真正有效的药物稳定地排到候选库前部，同时说明为什么以及这个预测有多可信？”**

这才是整个项目最终需要建立的闭环。
